# GameLingo Direct 3.5.2 — OCR 调度与自动源语言修复

更新：2026-10-24。版本 3.5.2（Build 12），目标工作流 `ios-direct-unsigned`。

> 这是源码级变更记录，并不代表已通过 Codemagic 或 iPhone 真机验收。3.5.1 真机诊断显示 OCR 经常在低置信度文本上额外执行 Accurate 模式，且静态帧抑制与多帧确认互相阻塞。

## 已修改

- **自动源语言**：新建游戏与原始“默认游戏”配置默认 `auto`（原始默认配置做一次性迁移并立即持久化）；其他已配置游戏仍保留手动语言选择。
- **本机 OCR**：`VNRecognizeTextRequest.automaticallyDetectsLanguage` 启用；根据本机 Vision 实际支持语言提供优先短名单，实时 Fast OCR 最多五种，Accurate OCR 最多八种。
- **本机翻译**：对已识别的文本使用 `NLLanguageRecognizer` 确认源语言；日语假名与韩语谚文优先归类。不能确定语言时保留现有字幕，不向苹果翻译传入 `auto`；已是简体中文的内容不重复翻译。
- **其他翻译入口**：整屏菜单、截图菜单、截图本机翻译、可选在线服务均不再把 `auto` 作为语言代码。自动语言无法确定的菜单可保存文字，但暂停自动翻译等待人工选择。
- **OCR 延迟**：快速模式只有空结果或严重低置信度（低于 0.42）才触发同步 Accurate 重扫；平衡模式保留 0.66 触发线。中等置信度通过短间隔多帧稳定性确认。
- **静态屏幕**：等待确认的低置信度候选文字不再被三秒静态跳过门槛阻挡。
- **采集频率**：ScreenCaptureKit 快速/平衡/省电模式分别限制为 10/6/3 FPS，真正的 OCR 执行频率仍由独立调度控制。
- **底部 OCR**：仅当补扫帧和当前画面的底部指纹一致时，才合并补扫文字，防止旧页面文字混入新页面。
- **回归测试**：新增 `tests/auto_language_smoke.swift`，由 Codemagic Mac 对语言识别进行基础测试；发布静态检查同步更新。

## 实测限制

- 语言包仍需在本机按需安装；自动识别语言**不是自动下载所有翻译包**。Apple Translation 的 installedSource 初始化必须指定已安装的具体语言。
- 极短文字、纯数字、通用 RPG 缩写、纯汉字日文及混合语言段落仍可能无法可靠判定；这些场景优先不猜测，可在“游戏配置”手工设置具体语言。
- Vision 多语言 OCR 支持和性能因 iOS SDK、设备及识别等级而变化；已加入 Codemagic 主机冒烟检查，但必须实测跨语言游戏画面。
- 即使测得采集到 PiP 提交延迟，也不能据此认定画面最终出现在屏幕上的时间；PiP 受系统管理。

## 验收步骤

1. 在 Codemagic 运行 `ios-direct-unsigned`；检查 `auto_language_smoke`、`ocr_quality_smoke`、Swift 语法和 Xcode 构建。
2. 先用同一款日语游戏，对比 3.5.1 与 3.5.2：查看 OCR P50/P95、复检比例、采集→译文与 PiP 提交耗时。
3. 再用英文、韩文、简体中文界面测试；确认自动识别正确，未安装语言包时明确提示而非默默切换在线服务。
4. 比较静态对白停留时两帧/三帧验证是否能完成；高速切换菜单时旧底部文字不会出现。
5. 分别测试开关底部 OCR、快速/平衡/省电模式，连续 15–30 分钟观察设备发热、电池和 PiP 稳定性。

已提交源码，以上验收步骤**仍未实际执行**。
