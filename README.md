# GameLingo Direct

在 iPhone 上玩日语游戏时，我经常需要停下来查菜单、看对话，尤其是一些没有中文的 RPG。GameLingo Direct 就是为这件事做的：读取屏幕上的游戏文字，翻译成中文，再用画中画小窗显示出来。

目前主要面向 iPhone，默认使用 Apple 提供的本机文字识别和翻译能力，不需要接入 OpenAI API。项目还在持续调整，尤其是不同游戏的字体识别、后台采集和 PiP 表现，需要在真机上逐个验证。

## 现在能做什么

- **游戏内双语字幕**：日文在上，中文在下。也可以只看中文、使用多行双语或高密度排版。
- **自动翻页**：小窗可以连续播放已翻译的内容，支持暂停、前后翻页、调整停留时间；中文朗读可单独开启。
- **整屏菜单翻译**：装备、任务、商店等静态界面可以单独扫描。内容较多时在 App 内的「整屏文字」页查看，不必全部塞进小窗。
- **横竖屏游戏**：每个游戏分别保存识别范围，必要时手动调整方向。屏幕最下方还有一个可关闭的小字补扫选项。
- **游戏词库**：内置常见日语 RPG 术语和《勇者斗恶龙》专用词库；也能导入自己的 TXT 词库，多套同时启用。
- **本地历史与诊断**：保留译文记录，可以对照 OCR 原文、过滤结果和中文，方便找到错字、漏字的原因。

文字识别使用 Apple Vision。画面没有明显变化时会尽量复用已有结果；新画面到来后，优先处理较新的帧，减少积压。

## 安装

当前主要使用 **Codemagic 构建 + SideStore 安装**，没有提供 App Store 下载。

需要准备：

- 一台运行 **iOS 27 或更高版本**的 iPhone；
- 可以访问 GitHub 和 Codemagic 的电脑，Windows 也可以；
- SideStore，以及正常的 iOS 侧载签名环境。

构建步骤：

1. 在 Codemagic 中选择这个仓库的 `main` 分支。
2. 运行 `ios-direct-unsigned` 工作流，使用带 iOS 27 SDK 的 Xcode 环境。
3. 构建成功后，在 Artifacts 中下载 `GameLingoAI-Direct-iOS27-unsigned.ipa`。
4. 使用 SideStore 对 IPA 签名并安装到 iPhone。

生成的是**未签名 IPA**，不能直接在手机上点开安装。侧载应用的签名有效期和重新签名要求取决于所使用的 Apple ID 与 SideStore 环境。

如果 Codemagic 编译失败，可以查看构建产物里的 `compiler-errors-direct.txt` 和 `xcodebuild-direct.log`。完整日志通常比截图更容易定位问题。

## 第一次使用

1. 打开 GameLingo Direct，选择游戏文字的源语言。第一次使用某个语言时，按提示准备 Apple 系统翻译语言包。
2. 新建或选择一个游戏配置。先用默认识别范围试运行，漏字时再调整竖屏、横屏扫描区域。
3. 开启画中画字幕，按 iOS 提示授权屏幕捕获，然后切回游戏。
4. 普通剧情看 PiP 即可；遇到装备列表或大量静态文字，可以使用整屏菜单扫描，再到「整屏文字」查看。
5. 如果底边对白经常漏掉，在游戏配置的「识别」中打开底部强化识别。它会增加一部分 OCR 工作量，设备发热或耗电明显时可以关闭。

游戏配置分成「识别」「词库」「翻译」「偏好」四组。字幕模式、自动播放和语音朗读在偏好设置里调整。

## 自定义词库

在「游戏配置 → 词库」中可以导入 TXT。建议使用 UTF-8 编码，也支持 UTF-16。每行一条，使用等号或 Tab 分隔日文与中文。

~~~text
# 词库名称：我的 RPG 词库
# 以 # 开头的行作为备注

ホイミ=霍伊米
スライム=史莱姆
攻撃力=攻击力
守備力=防御力
~~~

[下载词库示例](examples/游戏术语词库模板.txt)

导入后会显示有效词条、重复项和格式错误。不同 TXT 会作为独立词库保存，可以单独开关，也可以一键全部启用。每个游戏有自己的启用组合；所有已导入词条可以一起搜索。

同一日文有多种译法时，优先级是：

**当前游戏手动修改 > 已启用 TXT 词库 > 内置游戏术语 > 翻译引擎**

TXT 之间出现同名词条时，后导入的词库优先。《勇者斗恶龙》专用术语可以直接一键启用，不需要逐条添加。

## 翻译方式

默认使用 **Apple 本机翻译**。不使用在线翻译服务时，游戏 OCR 文字不会提交给第三方翻译 API；系统语言资源按需下载，不直接打包进 IPA。

如果需要在线翻译，目前有这些接口选项：

| 服务 | 设置方式 |
| --- | --- |
| MyMemory | 无需密钥，受公共额度限制 |
| LibreTranslate | 填写服务地址，按实例要求提供密钥 |
| Microsoft Translator | API Key；部分 Azure 资源还需要 Region |
| DeepL | API Key |
| Google Cloud Translation | Google Cloud 项目和 API Key |
| 自定义 REST API | HTTPS 地址、鉴权信息及请求/响应字段 |

在线服务**不会默认启用**。需要自己选择服务、填写必要信息并通过连接测试。密钥保存在 iPhone Keychain。启用在线模式后，识别到的游戏文字会发送给所选服务，原始截图不会作为翻译请求上传；手动导入的截图仍按本机流程处理。

有些服务提供免费额度，但可能要求开通计费账户，超过配额也可能收费。App 内的每日字符上限只用于本地保护，不是第三方账户的真实余额。实际规则以服务商为准。

## 需要知道的限制

GameLingo Direct 并不修改游戏文件，也不会把中文直接写回游戏原来的文字位置。翻译结果显示在 iOS 管理的 PiP 小窗及 App 的完整文字页面中。

目前还要注意这些情况：

- 系统是否允许持续采集、PiP 能否在游戏前台保持运行，受 iOS 和具体游戏影响。
- 美术字体、极小字号、运动中的文字以及被遮挡的文本，OCR 仍可能认错或漏掉。
- 小窗空间有限；菜单内容较多时，建议到「整屏文字」看完整列表。
- OCR 支持的语言与 Apple 本机翻译可下载的语言不完全相同。
- 开启底部补扫、语音朗读或在线翻译后，耗电、网络用量和延迟可能发生变化。

这些限制暂时不能靠提高扫描频率彻底解决。

## 开发和构建状态

当前源码版本：**3.5.1（Build 11）**。

本版主要调整实时字幕的处理方式：PiP 的文字排版和视频帧生成交给独立 CoreText 队列，复用视频缓冲；新对白优先显示，旧字幕不再挡住新译文。底部小字精确 OCR 和整屏菜单共用较低优先级的扫描队列，不阻塞快速对白 OCR。历史记录写入也会适当合并，减少主线程短暂停顿。

「运行诊断」增加了采集排队、OCR、翻译、字幕绘制，以及采集到 PiP 视频帧提交的最近一分钟 P50/P95 统计。它们用于比较不同游戏与设置，不能直接代替实际屏幕呈现延迟。

[3.5.1 性能审核与真机验收项](docs/RELEASE_AUDIT_3_5_1.md)。

`main` 分支保留的是 iOS 27 的单 App 直采方案，不使用 App Groups 或 ReplayKit 广播扩展。Xcode 工程由 `tools/build_xcodeproj.py` 在构建时生成，Codemagic 负责运行静态检查、Swift 检查及 iOS 编译。

此前中文朗读代码的编译错误已经修复。3.5.1 的新视频渲染器仍需要通过 Codemagic Xcode 27.1 完整编译及真实 iPhone 的 PiP 验收；当前源码提交不等于已实测达到某个延迟数字。仓库里的代码更新不代表已经在所有 iPhone 上验证通过。

代码主要在 `ios/GameLingoAI/`，构建配置是 `codemagic.yaml`。需要看具体改动和测试范围，可以参考 [3.5 源码审核记录](docs/RELEASE_AUDIT_3_5.md)。

如果发现问题，最好同时提供游戏截图、OCR 诊断文本或 Codemagic 编译日志。分享前记得去掉个人信息和 API Key。
